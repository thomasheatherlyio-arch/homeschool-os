# Doc 04 — Student Dashboard (MVP)

**Purpose:** one place Thomas and Shiloh both look at to see what's happening right now, what's done, and how the Circle (Doc 01) is filling in. In this MVP phase, the "dashboard" is this document plus a weekly conversation in Claude — Phase 2 (Doc 05) upgrades this to something closer to a real live dashboard.

---

## 1. Weekly Rhythm

**Monday — Planning.** Set 3–5 "missions" for the week, spread across quadrants (not all academics, not all one interest). Each mission gets a quadrant tag, a plain-language description, and a "done looks like" definition (what evidence will exist when it's finished).

**Daily — Execution + capture.** Work happens; evidence gets captured same-day (photo, file, note, screen recording) rather than reconstructed on Friday from memory. This directly targets the organizational gap from Shiloh's history — the habit being built is "capture as you go," not "produce a report at week's end."

**Friday — Review.** Walk the week's missions: done / partial / not done, honestly. Update the Circle's five quadrant scores (0–10). File evidence into the log (Doc 03 for academic items; a general evidence folder for everything else). Talk about what made the week work or not — system diagnosis, per Principle 1 in Doc 00, not blame.

**Quarterly — Headmaster Review.** Thomas reviews the full quarter against Doc 03's completion checklist and this dashboard's mission history, updates grade-level designation if warranted, and archives the quarter as a portfolio snapshot.

---

## 2. Dashboard Sections (what this doc/conversation should always be able to show)

1. **This Week's Missions** — the 3–5 active items, with quadrant tags and status.
2. **Circle Snapshot** — current 0–10 score per quadrant, and which way it's trending.
3. **Evidence Inbox** — items captured but not yet filed into the formal log.
4. **Mentor Session Log** — date, which Knight, quadrant, what was discussed, what changed as a result.
5. **Open Contracts** — any project-level agreements currently active (see Section 3).

## 3. Project-Level Contracts

Bigger missions (a multi-week entrepreneurship project, a fitness goal, a big academic push) get their own lightweight contract, modeled on the Founding Agreement in Doc 00 §7: what Shiloh is committing to, what Thomas provides in return, what "done" looks like, and the deadline. This keeps the "contracts are literal" principle alive at the project level, not just the founding level.

## 4. Where Google Forms Fits

A weekly submission form is a natural MVP-to-Phase-2 bridge — it can exist now even before any automation is built. Suggested fields for a "Weekly Check-In" Google Form:

- What did you work on this week? (per quadrant, short answer)
- Time spent per quadrant (rough hours)
- Evidence link/upload (photo, file, doc)
- Self-rating per quadrant (0–10, matches Circle scale)
- What got in the way, if anything?
- What do you want to work on next week?

Thomas can stand this form up manually today; Phase 2 (Doc 05) covers wiring it to auto-update this dashboard.
